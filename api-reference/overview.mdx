## Introduction

The Verbalize API is a Next.js API route that processes documentation text through Vale CLI to provide real-time linting feedback. The API is designed for technical writers who need to validate content against style guides like Google, Microsoft, and Red Hat.

## Architecture

The API follows a simple request-response pattern:

```
┌─────────────────┐
│  Client Request │
│  POST /api/lint │
└────────┬────────┘
         │
         │ JSON: { text, style, customRules }
         ▼
┌─────────────────────────┐
│  Next.js API Route      │
│  /app/api/lint/route.ts │
└────────┬────────────────┘
         │
         │ 1. Validate input
         │ 2. Create temp file
         │ 3. Execute Vale CLI
         ▼
┌─────────────────┐
│   Vale Engine   │
│  (CLI Process)  │
└────────┬────────┘
         │
         │ Apply style rules
         │ Generate diagnostics
         ▼
┌─────────────────────────┐
│  JSON Response          │
│  Array of ValeAlert     │
└─────────────────────────┘
```

## Base URL

The API is accessed at the following endpoint:

```
POST /api/lint
```

<Info>
The API is serverless and deployed as a Netlify Function with a 10-second timeout limit.
</Info>

## Authentication

No authentication is required. The API is publicly accessible and designed for open use.

## Request Format

All requests must use:
- **Method**: `POST`
- **Content-Type**: `application/json`
- **Body**: JSON object with required fields

## Response Format

The API returns JSON responses in two formats:

### Success Response

An array of `ValeAlert` objects:

```typescript
interface ValeAlert {
  Action: {
    Name: string;
    Params: string[] | null;
  };
  Span: [number, number];
  Check: string;
  Description: string;
  Link: string;
  Message: string;
  Severity: string;
  Match: string;
  Line: number;
}
```

**Status Code**: `200 OK`

### Error Response

An error object with a descriptive message:

```json
{
  "error": "Error description"
}
```

**Status Codes**: `400`, `500`

## Rate Limits

No explicit rate limiting is enforced, but the API is subject to:

- **Concurrent Request Limits**: Multiple simultaneous requests may be queued
- **Timeout Limits**: 10-second execution timeout per request
- **Size Limits**: 1MB maximum text length

## Temporary File Processing

The API creates temporary files during processing:

1. **Temporary Directory**: Created in system temp directory with prefix `vale-`
2. **Document File**: `doc.md` written with user text
3. **Configuration File**: `.vale.ini` generated dynamically
4. **Styles Directory**: Contains symlinks to built-in styles and custom rules
5. **Cleanup**: All temporary files are removed after processing

See the [Vale Integration](/api-reference/vale-integration) page for detailed implementation.

## Error Handling

The API implements comprehensive error handling for:

- Input validation failures
- Vale execution errors
- File system errors
- JSON parsing errors
- Timeout errors

See the [Error Handling](/api-reference/error-handling) page for complete error codes and responses.
